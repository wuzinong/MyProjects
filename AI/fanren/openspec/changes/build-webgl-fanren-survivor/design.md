## Context

项目目前只有 PRD、272 张主要为 1024×1024 的 PNG、2 张动画预览图和 29 个独立 HTML 动效，没有应用代码、素材语义或授权清单。首版需要在桌面与移动浏览器中实现高密度 2D 割草战斗，同时承载洞府局外界面，并避免把来源不明的素材直接打入发布包。

## Goals / Non-Goals

**Goals:**

- 交付可从洞府进入“血色禁地”、完成 10 分钟战斗并带回成长资源的纵向切片。
- 以数据配置表达技能、敌人、波次、掉落和成长数值，便于不改代码地平衡。
- 在中端桌面设备 1080p 下以 60 FPS 为目标、在中端移动设备以 30 FPS 为底线，支持至少 500 个活跃敌人和 1,500 个视觉实体。
- 建立可追溯、可替换、受授权门禁保护的素材管线。
- 让存档、随机数与战斗逻辑可测试并可向后迁移。

**Non-Goals:**

- 首版不实现联机、账号云存档、PVP、拍卖行、付费系统或服务端反作弊。
- 首版不覆盖全部境界、秘境、72 口飞剑的局外逐口炼制、符箓绘制小游戏及完整剧情。
- 不承诺将现有全部素材投入游戏；来源或授权无法确认的素材只进入隔离清单。
- 不复刻影视、动画或其他游戏的受保护视听内容；发布前须完成 IP 与素材授权审查。

## Decisions

### 1. 使用 Vite、TypeScript 与 PixiJS 构建单页游戏

PixiJS 提供直接的 WebGL 2D 批处理、纹理图集、粒子和滤镜能力，同时允许战斗模拟保持框架无关。DOM 仅承载加载、无障碍文本、设置和复杂洞府面板，战斗场景与 HUD 使用 PixiJS，避免每帧跨 DOM/Canvas 同步。

备选 Phaser 提供更完整的场景和物理系统，但其通用实体/物理抽象对数百敌人的定制空间索引并非必要；纯 WebGL 则会显著增加资源、字体与批处理维护成本。

### 2. 固定步长模拟与表现层分离

战斗域以 60 Hz 固定步长更新纯 TypeScript 状态，渲染按浏览器帧率插值。实体使用数值 ID、结构化数组、对象池和均匀网格空间索引；范围查询、碰撞和自动索敌不依赖 Pixi DisplayObject。暂停、升级选择和结算通过显式状态机冻结模拟。

这比逐实体面向对象组件更利于稳定帧耗与自动测试，代价是系统边界和数据同步需要更严格的约束。

### 3. 配置驱动内容并在启动时做模式校验

技能、法宝、心法、灵宠、敌人、波次、五行系数、掉落和境界数据存放在版本化 JSON/TypeScript 配置中，使用 Zod 在开发和构建阶段校验。效果由受控的 effect type 注册表解释，不执行配置中的任意脚本。

这样策划数值可独立调整，也避免动态代码带来的安全与可维护性问题。复杂机制仍通过已注册的 TypeScript 系统实现。

### 4. 首版战斗切片

血色禁地由确定性种子驱动，按 PRD 的 0–2、2–5、5–8、8–9:50、9:50–10:00 阶段调度。基础技能包括火弹术、冰锥术、风刃术、地刺术；法宝包括青竹蜂云剑和金光砖符宝；心法包括长春功、罗烟步、太一诀；灵宠包括噬金虫。

青竹蜂云剑在局内用“剑意层数”映射 12/36/72 口里程碑，首版不要求逐口渲染全部飞剑。大庚剑阵采用有限粒子与着色器表现，伤害判定使用独立区域系统。

### 5. 三维资源与统一伤害管线

实体拥有生命、法力、神识及肉身/法力/神识防御。伤害事件按伤害通道、元素、来源标签、暴击、克制和状态修正依次结算；五行采用可配置矩阵，风/雷/冰默认无基础五行克制，仅由技能规则赋予加成。所有恢复、消耗、护盾、麻痹、减速与破甲都通过事件管线记录，便于调试和测试。

### 6. 版本化本地存档与受限离线收益

首版用 `localStorage` 保存小型 JSON 存档，包含 schema version、境界、资源、洞府状态、解锁项、设置和最后可信时间。加载时先校验再逐版本迁移，写入采用临时键后切换主键。离线绿液按本机经过时间计算，但单次最多结算 12 小时且总量不超过 12 滴；检测到时钟倒退时不发放收益并提示玩家。

不采用 IndexedDB 是因为首版存档体积很小；若后续加入回放或大量库存，再迁移到 IndexedDB。

### 7. 素材先登记后迁移

保留 `assets/` 原件，生成含原文件、哈希、尺寸、视觉类别、候选用途、来源、许可证、审核状态和目标名的清单。经审核素材复制并优化到 `public/assets/<category>/<semantic-name>.<ext>`，由 manifest 绑定稳定逻辑 ID；代码禁止引用 `screen_*.png` 或 `code_*.html`。

现有 HTML 动效只作为参考：提取原创且授权明确的 GLSL/SVG 后重写为运行时 effect module，不以 iframe 或 Tailwind CDN 方式嵌入游戏。

### 8. 渐进降级与性能预算

启动时检测 WebGL 支持、纹理上限和设备像素比。渲染器将 DPR 上限设为 2，并提供低/中/高三档：降低粒子、阴影、滤镜、飘字和渲染分辨率，但不改变伤害判定与敌人逻辑。资源按场景分包加载并展示真实进度；上下文丢失时暂停并尝试恢复，失败则返回可诊断错误页。

## Risks / Trade-offs

- [题材与素材可能缺少商业授权] → 发布构建只接受清单中 `approved` 的素材，并设置独立法务/IP 审核门禁；开发期提供原创占位图。
- [1024×1024 原图过多导致显存与下载量过高] → 裁切透明边、生成多分辨率 WebP/纹理图集、按场景懒加载，并设包体预算。
- [高密度敌群引发 CPU 或 GC 抖动] → 使用对象池、空间网格、无分配热路径、采样性能面板和压力场景回归。
- [移动端 WebGL/音频行为差异] → 首次手势后初始化音频，提供画质档位、触控安全区和主流移动浏览器实机矩阵。
- [本机时间可被修改以获取离线资源] → 首版限制离线收益并记录异常；没有服务端时明确接受无法彻底防作弊的取舍。
- [PRD 范围远超一个首版] → 以单秘境纵向切片验收，其他系统只保留扩展接口，不提前实现。

## Migration Plan

1. 建立工程、测试和 CI 基线，并保留现有 `prd.md` 与原始 `assets/` 不变。
2. 生成素材清单和授权状态；仅迁移首版实际需要且审核通过的素材。
3. 先交付占位素材驱动的战斗切片，再接入正式纹理、动效和音频。
4. 接入洞府成长和版本 1 存档；开发期间旧的无版本测试数据可由显式“重置存档”迁移。
5. 在发布候选版本中执行性能、移动端、上下文恢复、存档迁移和授权清单检查。
6. 若上线失败，回滚静态站点版本；存档迁移必须保持向前读取，禁止自动降级覆盖较新存档。

## Open Questions

- “凡人修仙传”名称、角色、法宝与视觉素材的具体发行授权范围需在公开发布前确认。
- 正式音频素材、中文字体及其许可证尚未提供，首版实现时需选择可商用资源或原创占位。
- 低端移动设备的最终同屏敌人数应在首个压力测试原型后确定。
